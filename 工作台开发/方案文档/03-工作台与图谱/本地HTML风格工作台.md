# 本地 HTML 风格工作台

## 1. “本地 HTML”的含义

交付形态为浏览器内使用的网页应用，采用 HTML/CSS/JavaScript 呈现参考图风格。本机可用版通过本地服务启动后访问回环地址；不是双击一个 HTML 文件就能拥有安全多人后台。

如需零安装演示，可单独做纯静态演示页，明确标注“演示数据，无真实权限与团队同步”。正式正文仍以本地服务端数据库为准。

## 2. 页面结构

- 顶栏：工作台名称、项目切换、搜索、新建、上传、保存状态、当前账号。
- 次栏：当前项目/系统/功能路径，数据模式标签（演示/本机/团队），最近更新。
- 主区左侧约 42%：关系图；右侧约 58%：分类卡片。分隔条可拖动，偏好保存在当前设备。
- 浅灰背景、白色面板、细边框、小圆角、紫蓝主色；项目节点暖色，系统节点主色，功能节点白底。文字和图例辅助表达，不仅依赖颜色。
- 原图右侧四列卡片改为响应式 2–4 列；窄窗口优先切换图谱/内容页签，不把正文压到无法阅读。

推荐初始样式变量：背景 `#F5F6FB`、面板 `#FFFFFF`、主色 `#5651E5`、正文 `#1F2937`、边框 `#E5E7EB`。这是参考风格提案，实施时验收文字对比度与键盘焦点。

## 3. 图谱

项目 → 系统 → 功能用包含关系展示；依赖、触发、引用为不同关系类型，线型及图例区分。关系由用户设置，不从文案臆测。

- 缩放、平移、展开/收起、适应画布、重置布局、只看当前关联。
- 默认只展开当前系统，以 500 节点基线控制可视复杂度。
- 节点点击只改变当前选择和右侧过滤；双击/“阅读”进入文档，不让一次点击意外进入编辑。
- 拖动位置只保存布局偏好；不能因节点位置接近就建立业务关系。
- 包含关系必须无环；跨功能依赖允许显式标注，循环依赖需提示业务复核，不自动删边。
- 可选 React Flow 作为渲染及交互基础，业务模型和权限由项目实现。[官方文档](https://reactflow.dev/learn)

## 4. 分类卡片

默认分组：概述与功能、规则、情况与玩家看见、配置与数据、UI与资源。分组映射统一分类，不另建平行资料库。

卡片字段：标题、正文摘要、分类/子类型、所属功能、阅读入口。摘要是可重建投影；用户若需要编辑“摘要”，将其作为正文明确的摘要块维护。

点击卡片 → 完整文档定位 sectionId/blockId，并高亮短暂提示；从正文点击所属功能 → 返回图谱并聚焦对应节点。路由建议 `/projects/:projectId/documents/:documentId?view=read#block-...`，参数只用于定位，服务端仍鉴权。

策划卡片和图谱不展示草稿/已确认、完成度、缺项数量、验收或待确认事项入口，也不按完成程度给节点描边；用颜色和线型区分业务对象与关系。游戏运行状态以及保存、加载、错误反馈照常表达。

## 5. 阅读与编辑

完整阅读模式默认隐藏或收起关系图，保留章节目录、正文、关联内容/原件侧栏。阅读页不能只展示摘要或逐卡碎片。

编辑按钮切换为同篇文档的编辑模式，保留阅读位置；未授权用户不显示编辑操作，后端仍校验写权限。返回阅读前刷新保存队列；若失败则保留草稿并明确提示。

UI章节提供示意图与控件说明并排模式，控件编号互相定位；图片支持放大、原尺寸查看；页面切换和红点规则绑定当前 UI 页面。

## 6. 搜索与状态反馈

搜索范围可切换项目、系统、功能、分类。标题、正文、配置字段和附件名称可搜索，结果带命中片段和定位；首版不承诺图片 OCR、XMind 内部或全部附件全文解析。

空项目显示新建/导入；未匹配显示当前过滤条件；损坏文件显示可操作的转换报告；无权限采用统一不可访问提示，避免泄漏文档标题。大图懒加载，卡片列表分页/虚拟化；图谱和正文加载失败分别重试，不能清空用户已有草稿。

## 7. 最小前端模块

`workspace-shell` 顶栏和布局；`graph` 图谱；`catalog` 卡片和过滤；`document-reader` 阅读渲染；`document-editor` 编辑器；`search` 检索；`imports` 上传预览；`auth` 登录和账号状态。页面只使用统一 API 客户端，不直接访问数据目录。

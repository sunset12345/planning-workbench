# 飞书式编辑器实施方案

## 1. 定位和模块边界

目标是清晰的块式文档编辑、快捷插入、自动保存和完整阅读体验。不是完整复刻飞书，也不接入飞书账号或文档服务。

建议使用 Tiptap / ProseMirror 体系作为编辑核心，前端统一以有版本的 JSON 文档结构持久化。Tiptap 官方支持 JSON/HTML 输出并推荐 JSON 持久化；项目自行负责保存服务、权限和业务模型。[官方持久化说明](https://tiptap.dev/docs/editor/core-concepts/persistence)

编辑内核只处理光标、选区、块结构及撤销；文档服务负责版本与权限；资源服务负责上传和鉴权；工作台从正文投影分类卡片。不要把数据库写入、权限判断和图谱业务塞入编辑扩展。

## 2. 能力矩阵

以下是计划级别，不代表已经实现。安装前核对所选版本、许可证及扩展是否收费；不默认购买商业插件，不依赖供应商托管协作服务。

| 能力 | P1 本机版 | P2 团队版 / 后续 | 实现或验收重点 |
| --- | --- | --- | --- |
| 标题、段落、粗斜体、删除线、链接 | 必须 | 保持 | 文档目录与稳定锚点 |
| 有序/无序列表、任务列表、引用、分割线、代码块 | 必须 | 增强 | 缩进、撤销重做、键盘可操作 |
| 斜杠插入菜单、浮动工具条 | 必须做基础菜单 | 搜索更多块 | 中文输入法组合期间不抢输入 |
| 块拖拽、移动、复制、删除 | 基础上下移动必须；拖拽增强可后置 | 拖拽完善 | 复制生成新 ID，移动保留 ID |
| 基础表格 | 必须 | 合并单元格/复杂布局可后置 | 增删行列、横向滚动；不计算公式 |
| 图片、图注、放大、基本尺寸 | 必须 | 并排图片/布局后续 | 上传完成再提交有效资源引用 |
| 内部文档/章节引用 | 必须 | 引用回链面板增强 | 重命名不破坏链接；权限过滤 |
| 折叠标题、目录、阅读/编辑切换 | 必须 | 更多阅读设置 | 收起图谱后连续阅读 |
| Word/网页粘贴 | 基础必须 | 保真增强 | 清洗样式和不安全 HTML；复杂格式提示 |
| 查找 | 必须 | 替换增强可后置 | 编辑内查找与跨文档搜索分开 |
| 自动保存、手动保存、历史 | 必须 | 保持 | 见保存状态机 |
| 评论、回复、解决 | 不在 P1 | P2 可选 | 整篇或块锚定，不承诺精确字符级批注 |
| @成员、通知 | 不在 P1 | 另行确认 | 先做应用内通知，不默认发邮件 |
| 实时共同编辑、在线光标 | 不在 P1/P2基线 | P3 | 单独评估 CRDT、授权和恢复 |
| 复杂分页、公式、数据库表、多维表格 | 不在首版 | 需求驱动 | 不宣传等价支持 |

## 3. 内容结构与稳定引用

文档存 `schemaVersion` 和编辑树；章节是带 `sectionId`、`categoryKey` 的顶层容器，内部块带 `blockId`。服务端检查 ID 唯一、节点类型与嵌套合法、资源属于有权项目。新块生成稳定 ID；粘贴复制生成新 ID，块移动保留 ID。

正文是唯一权威内容；章节索引、纯文本索引、卡片摘要可以重建。不要另外维护一份“卡片规则正文”。某块所属分类来自章节，卡片可带展示子类型（规则/情况/UI），只保存引用与展示元信息。

## 4. 自动保存和故障处理

推荐初值：停止输入 1.5 秒触发保存，持续输入最多 10 秒发起一次；实际根据性能测试调优。输入法组合未结束时不截断组合文字。

状态：未修改 → 有修改 → 保存中 → 已保存（服务器时间、版本号）；失败 → 保存失败/待重试；409 → 冲突待处理。只有服务端提交成功才显示“已保存”。

- 每篇文档单写请求队列；保存中继续输入只更新待保存缓冲，旧响应不能覆盖新输入。
- 请求携带 `baseRevision`、唯一 `requestId`、本次快照。服务端幂等重试且检测版本。
- 成功后把本次快照标为已保存；若之后仍有输入，立即保持“有修改”并继续队列。
- 网络断开保留本页内容；可选 IndexedDB 草稿按用户/项目/文档隔离，提示此设备仍保有草稿。缓存不是备份，退出登录清除缓存或先提示用户导出未提交内容。
- 手动保存用于立即刷出队列。离开/关闭前有未保存内容则警告；不能保证浏览器强制结束前必定提交。
- 失败重试使用原 requestId，不能无限高速重试；401 停止提交并保留草稿，重新认证后重新校验权限及版本。

## 5. 并发、撤销和版本

P1/P2 使用整篇文档乐观锁：两人从 r12 编辑，甲保存为 r13，乙仍以 r12 保存时返回 409，乙的内容完整保留。对比本人草稿和最新版，允许复制内容、手动合并或另存新文档；不默认“强制覆盖”。

撤销重做是当前编辑会话内操作，不是回滚服务器历史；历史恢复生成一个新版本并记录来源版本。恢复也带当前 revision 检查，避免恢复操作覆盖刚到达的新改动。

自动保存每次成功可形成不可变修订；为避免历史列表噪声，界面按编辑会话聚合展示，手动“命名版本”作里程碑。P1 默认不自动删除历史，容量和保留期由部署策略决定。

## 6. 未来协作边界

P2 评论记录 commentId、documentId、blockId、创建时 revision、作者及状态。块移动后评论跟随 ID；块被删除则标为失去锚点，仍在评论面板可读。首版不做字符选区长期映射。

P3 若引入 CRDT，必须整体替换编辑合并层，定义离线更新、Schema 迁移、存储压缩、逐文档 WebSocket 授权及移除成员后的连接撤销；不能把实时协作插件加上后继续假设整篇 revision 冲突模型即可解决全部问题。

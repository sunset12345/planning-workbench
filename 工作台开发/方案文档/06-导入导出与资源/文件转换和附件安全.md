# 文件转换和附件安全

## 1. 支持范围

| 类型 | 首版行为 | 限制与保留 |
| --- | --- | --- |
| Markdown | 转为可编辑块，解析标题/列表/表格/链接/图片 | 原始 MD 保留；不运行内嵌 HTML 或脚本 |
| DOCX | 转基础标题、正文、图片、列表及表格 | 保留原件；复杂分页、浮动对象、修订批注可能降级 |
| XLSX | 工作表切换、单元格预览和原件下载 | 只展示保存结果；无缓存值则显示公式及未计算，不执行公式/宏/外链 |
| PNG/JPG 等允许图片 | 校验后生成预览，关联块/UI页面 | 保留来源；首版不接受活动 SVG 直接内联 |
| XMind | 保存源文件、用户提供配套预览图 | 不编辑内部节点，不承诺解析预览 |
| ZIP | 作为正文+资源包安全解压、预览并确认 | 不支持任意可执行项目；不递归解压嵌套 ZIP |

DOCX 可选 Mammoth 做结构转换。其官方文档明确提示不负责清洗输入，因此必须另做 HTML/链接清洗；支持范围以实际样例验收为准。[Mammoth 官方项目](https://github.com/mwilliamson/mammoth.js)

## 2. 两阶段导入

上传 → 临时隔离 → 文件识别/限额检查 → 安全转换 → 展示预览和警告 → 用户选择项目/系统/功能及分类 → 同名新增或替换 → 原子提交文档和资源引用 → 清理临时产物。

预览不等于正式保存。任务失败不留下半篇已发布文档；确认重试要幂等。替换时保留历史、检查 baseRevision，不能因文件同名就覆盖。Word 转换后网页正文为编辑对象，原件标明“导入原件”和时间，不把网页编辑伪称已经同步回原 Word。

## 3. 转换报告必须包含

成功解析的段落/标题/表格/图片数量；不支持对象；缺失图片路径；复杂格式变化；失效链接；原件获取入口。警告需要用户可见，不能隐藏在服务器日志。

相对图片路径在包内规范化后映射到资源 ID，展示原相对路径便于修复；缺失图片显示占位和修复入口。对外部图片默认不自动抓取，避免泄漏访问行为及服务端请求伪造；需要时提示用户上传本地图片。文件中的链接可显示但只允许安全协议，外部跳转明确告知。

## 4. 安全要求

- 扩展名、MIME、文件签名联合检查；不能只信浏览器声明。
- 存储名由服务端生成，用户文件名仅作显示；禁止目录穿越、绝对路径、符号链接、Windows 盘符/UNC 路径等逃逸。
- ZIP 同时限制压缩大小、累计解压大小、单文件大小、条目数、压缩比、深度、转换时长；不得先无上限解压再检查。
- 可作为实施初值：单文件 25 MiB，单包 100 MiB，累计解压 300 MiB，条目 2,000，图片总像素 40MP；都属于待实测调优配置，并非已实现保证。
- DOCX/XLSX 本身也是压缩容器，同样执行解压与资源消耗限额。转换任务设超时、内存限制、取消与重试；不执行脚本、宏、外部实体、嵌入程序。
- 对转换后 HTML 和粘贴内容统一白名单清洗；禁止 script、事件属性、危险 URL、未批准 iframe。只允许编辑器 Schema 支持的内容进入正文。
- 附件不放在无需鉴权的静态目录。未知或主动内容以下载附件方式返回，设置正确 MIME、Content-Disposition、nosniff，禁止浏览器当站点脚本执行。
- 防病毒扫描可后续接入；首版不能因未扫描就标注“绝对安全”。

## 5. 导出

P1 必须提供单篇 Markdown（含资源 ZIP）和完整项目包；浏览器打印/PDF作为阅读副本，明确分页可能变化。DOCX 导出列为 P2 增强，不借“能导入”推断也能保真导出。

项目包包含 manifest（schemaVersion、导出时间、文件校验值）、项目/系统/功能、结构化文档、分类、显式关系、资源和所需原件。默认当前版本；导出选项明确是否包括历史，并估算体积。白名单认证数据、会话、主机路径及部署配置不导出。

导回已有项目默认“复制为新项目”，重映射 ID 和内部引用并保留追溯映射；整体恢复需单独确认，不能混用成覆盖导入。验收校验正文、图片、分类和关系的一致性。权限配置不自动从导入包生效，由目标项目管理员重新确认。

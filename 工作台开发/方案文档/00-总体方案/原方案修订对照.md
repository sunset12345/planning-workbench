# 原方案修订对照

| 原计划 | 本次调整 | 原因 |
| --- | --- | --- |
| 正式存储等待 GitLab 或 Google 二选一 | 默认本地服务端 + SQLite + 资源目录 | 用户要求本地白名单，不依赖第三方账号 |
| GitLab / Google 官方授权登录 | 服务端读取本地白名单并校验本地账号 | 登录源、权限和数据归属更清楚 |
| 原型 IndexedDB，正式资料放第三方平台 | IndexedDB 只作 P0 演示或草稿恢复缓存 | 浏览器存储不能代替可靠持久化与权限 |
| 文字描述富文本编辑 | 单列能力矩阵、稳定块 ID、粘贴清洗、自动保存及降级 | 使“飞书式体验”可实现、可验收 |
| 一个开发计划文档 | 中文功能目录拆分，README 导航 | 方便分模块实施与维护 |
| 左图谱＋右卡片 | 保留；明确完整正文、编辑模式和一源多视图 | 对齐参考图与完整策划案工作流 |
| 管理员/编辑者/阅读者 | 保留；区分白名单身份和项目成员权限 | 有账号不等于能查看全部项目 |
| 保存立即生效、版本冲突提示 | 保留；补充事务、幂等、响应乱序和草稿策略 | 防止静默覆盖或虚假保存成功 |
| Word/Excel/XMind 处理边界 | 保留；补充路径穿越、解压限制、附件鉴权 | 支持真实导入流程 |
| 100文档、500节点、600图片 | 保留为首轮基线；增加可记录的性能目标 | 便于在实际设备上验收 |

保留的关键约束：先原型、导入预览再确认、同名不自动覆盖、Word 原件保留、Excel 不执行公式、红点归入对应 UI 页面、关联关系人工明确设置、历史恢复生成新版本；策划内容只描述制作要求，不维护完成度、验收或待确认事项。

上传原件完整保存在[资料归档 / 上传副本](../../../资料归档/README.md)。这份对照不修改原件，仅说明 v2.0 决策。

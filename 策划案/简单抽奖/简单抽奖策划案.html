3. 功能逻辑与计算公式

本期：单池、单抽、可叠加资源奖励。正文定义类型、数量、计算与UI行为；具体资源和数量是附件中的示例配置。

抽奖主流程

双击节点直接改字；点击节点右下角“↗ 跳转”查看关联内容。编辑后应用修改，并下载当前 HTML 保存。

开放与刷新

新抽取要求配置有效、pool.enabled=true、角色等级≥unlockLevel。每日免费上限 dailyFree 为0或1，周期按 周期与免费次数公式 判断。读取页面、点击抽奖和跨周期时刷新；依据游戏统一时间。

选择消耗方式

已接受的抽奖优先确认和展示，不能再发起一笔。新操作按配置有效→开放→等级→空闲→刷新免费→选择消耗校验。freeRemaining>0 优先免费，否则检查抽奖前余额 B[costResourceId]≥costCount。资源不足不消耗。

抽取、发放、表现

按 概率与抽取公式 从 N 个条目中选且只选1个；按 消耗公式 扣除资源，按 数量与余额公式 发放该条目的固定count。成功结果确定并入账后才播放0.8秒过程表现。跳过只结束表现，不改变结果；结果为单对象，不设置领取步骤。

重复操作与恢复

SUBMITTING、PENDING、ANIMATING、RESULT时禁止新抽。明确失败不扣免费次数和资源；不明状态显示PENDING，确认原结果，不当失败重抽。离开不撤销已接受的抽取；返回补展示未看过的成功结果，恢复时不重播动效、不重复发放。

时间与配置边界

使用接受时的配置和刷新周期；接受后关闭奖池或修改权重不改变原结果。旧周期最后一秒接受、新周期展示，消耗旧周期免费，新周期资格保留。N=0、非正整数权重/数量、重复条目ID或引用缺失使整池不可用，禁止悄悄删除坏行后重新归一化。

计算公式、变量与边界

变量类型 / 单位含义
t / hint / UTC秒、小时t为接受抽奖的时间；h=resetHour∈[0,23]；固定UTC+8时区。
d / u / Dint|null / int / intd=usedCycleKey，u=freeUsed∈{0,1}，D为当前周期键。
F / C / B[x]int / 次、资源单位F为可用免费次数，C=costCount≥1，B[x]为抽取前资源余额。
N / w_i / Wint / 条、无量纲N为条目数；w_i>0；W为总权重，必须>0。
p_i / r / S_i比例 / int / intp_i范围(0,1]；r是均匀随机整数；S_i为累计权重。

周期与免费次数

D(t) = floor((t + 8×3600 - h×3600) / 86400)
usedToday = (d == D(t)) ? u : 0
F = max(0, dailyFree - usedToday)

时间达到刷新整点即进入新周期，等号归新周期；不累计未用次数。免费成功后 d=D(t)、u=usedToday+1；失败保持原值。

消耗

costType = (F > 0) ? free : resource
paidCost = (costType == free) ? 0 : C
新抽取可支付 = (F > 0) OR (B[costResourceId] >= C)

costCount是单个固定整数。余额等于C允许抽取；不使用尚未获得的奖励垫付本次消耗。

概率与抽取

W = Σ(w_i), i = 1..N
p_i = w_i / W
S_0 = 0; S_i = Σ(w_j), j = 1..i
r ∈ {0, 1, …, W-1}，每个整数等可能
选择唯一满足 S_(i-1) <= r < S_i 的条目 i

按id字符码点升序确定区间；采用左闭右开。r=0命中第一条，r=W-1命中最后一条。各次独立使用全池，同一条目可再次命中；无保底。

数量与余额

rewardCount = entries[i].count
B_after[x] = B_before[x]
             - (x == costResourceId ? paidCost : 0)
             + (x == result.resourceId ? rewardCount : 0)

发放数量直接取正整数，不二次随机、不乘权重。消耗与奖励引用同一资源时合并计算净变化。一次成功只结算一次。本版假设可叠加资源无业务容量上限；项目若有上限，接入前补齐溢出规则，不默认截断或重抽。

概率与数量的显示

若 0 < 100×p_i < 0.01：显示 <0.01%
否则 pct_i = floor(10000×w_i/W + 0.5) / 100
按两位小数显示 pct_i + %
数量：显示完整整数 + Resource.unit，不使用K/M缩写

仅显示时四舍五入；实际抽取使用原始整数权重。四舍五入后合计可能不等于100.00%，不人为修改最后一项。名称和图标通过引用读取，不能按特定资源ID写表现分支。

展开一个纯权重边界算例

权重[1,2,1]的区间是[0,1)、[1,3)、[3,4)，r=0/1/2/3分别命中第1/2/2/3条。把条目内容换成任意受支持资源，算法不变。算例不限制条目数。

概率行List<ProbabilityRow>，与entries一一对应每行图标、名称、固定数量、按“概率与数量的显示”公式计算的百分比；不按数量或概率重新排序。
滚动区固定6行可视，N>6纵向滚动底部规则说明和关闭按钮不滚动；N<6不补空白行。
状态正常 / 配置失效数据有效时显示；若配置关闭或失效，清除旧概率并显示暂不可用；关闭/返回回UI-01。

UI-03 抽奖结果弹窗

入口：本次奖励成功确定并结束或跳过表现后。展示本次唯一奖励、数量及已到账状态。

状态：普通奖励、稀有奖励、恢复展示。

控件显示 / 操作 / 反馈
03-A 奖励内容绑定单个DrawSuccess；rare控制普通/稀有表现，recovered控制是否重播；不得按具体resourceId分支。
03-B 已到账结果弹出前发放已完成，不设置领取按钮
03-C 关闭关闭返回UI-01并刷新资源/免费状态；重复查看不重复发奖

配置与状态：LotteryPool开放/免费/券消耗；LotteryReward奖励与概率；Resource/UiText图文；玩家等级、免费日期、券数量与当前抽奖结果。公共规则见 功能逻辑与计算公式。

本页红点：本页无红点；结果不产生可领奖红点。

状态显示 / 动效操作
普通成功：rare=false恰好1个结果卡；图标、名称、count、已到账；亮边0.35秒关闭按钮始终可用；关闭清理动效并刷新主页面。
稀有成功：rare=true同一个结果卡；背景光芒0.6秒，替代普通亮边不叠加普通特效；不改变概率、数量和到账时点。
恢复展示：recovered=true只显示静态结果，不重播过程/结果动效或音效重复打开不重复发奖；无领取按钮。

UI-04 通用提示与确认状态

入口：UI-01 操作未满足条件或结果暂不明确。明确告知是否扣费，以及玩家接下来可以做什么。

状态：券不足、等级不足、奖池关闭、明确失败、结果确认中。、名称全文（复用信息提示）。

控件显示 / 操作 / 反馈
04-A 条件提示券不足/等级不足/关闭时显示具体原因；确定关闭；不跳转未定义的充值商店
04-B 明确失败显示“本次未完成抽奖，未消耗资源”；确定后返回空闲
04-C 结果确认中显示“结果确认中，请稍后查看”；不显示失败或再抽按钮；允许离开，返回继续确认原结果

配置与状态：LotteryPool开放/免费/券消耗；LotteryReward奖励与概率；Resource/UiText图文；玩家等级、免费日期、券数量与当前抽奖结果。公共规则见 功能逻辑与计算公式。

本页红点：本页无独立红点；失败不消耗免费资格，主入口红点按“开放与刷新”规则重新判断。

原因 / 状态确切反馈操作与资源
名称全文显示所点条目的完整资源名称关闭返回来源页，无资源变化。
余额不足{name}不足，需要{count}{unit}确认关闭；资源与免费不变。
等级不足 / 关闭 / 配置无效显示对应原因，不能统一提示网络错误确认回主页面，主按钮按UI-01重新判断。
明确失败本次未完成抽奖，未消耗资源确认后IDLE；可再次按正常规则发起新抽取。
结果不明结果确认中，请稍后查看不显示失败、未扣费或再抽；允许离开；原结果确定后更新。

# 本地白名单与访问控制

## 1. 基本原则

本地白名单放在服务端配置目录，禁止打包进前端、放在静态目录或作为可下载附件。浏览器判断“名单里有我”不能作为安全认证。

白名单解决“哪些本地身份可登录”；项目成员表解决“登录后能访问哪些项目”。不使用 GitLab、Google、飞书等第三方账户，也不实现 OAuth。

## 2. 两种运行模式

| 模式 | 边界 | 默认建议 |
| --- | --- | --- |
| 本机单人 | 服务仅监听 127.0.0.1/回环；同机 OS 用户仍可能读取磁盘，网页权限不是磁盘加密 | 仍用白名单身份和会话，保留完整链路；不能无意监听全部网卡 |
| 局域网多人 | 中心主机运行服务；其他电脑通过浏览器访问；不共享数据库文件 | 启用受信 TLS、网络访问范围、登录限制、备份与会话撤销后再开放 |

局域网的 HTTP 会暴露传输中的登录和文档数据，因此不得把本机 HTTP 调试方案直接当团队部署方式；不要求用户绕过浏览器证书警告。

## 3. 示例文件结构（只说明形状）

```json
{
  "schemaVersion": 1,
  "users": []
}
```

这是一份空白示例，不包含可用账号或凭据。每个实际记录应具有稳定 userId、唯一 loginName、displayName、enabled、认证哈希字段、认证版本号；认证材料由部署负责人通过批准的安全流程初始化。不得保存明文密码、提供默认万能密码或把真实认证信息写入方案/日志。

如果采用本地用户名与密码，由服务端使用成熟密码哈希库（算法及参数在实现安全评审时锁定）验证，不自行设计加密算法。白名单通过受限文件权限和原子替换维护，加载前做 Schema 校验。P1 先通过离线配置维护，暂不提供网页账号管理器。

## 4. 登录和会话流程

1. 服务启动校验白名单；缺失/格式错误时拒绝对外认证，不退回“所有人可访问”。
2. 用户提交登录名和认证信息，服务端检查启用状态并验证，统一返回错误信息，限制失败频率。
3. 成功创建随机不透明会话标识，Cookie 设置 HttpOnly、SameSite；团队 TLS 设置 Secure。不把角色或密码哈希存在浏览器本地存储作为依据。
4. 每个请求验证会话、白名单启用状态/认证版本、项目成员资格；写请求另验角色、CSRF/Origin、对象归属。
5. 注销、禁用成员或移除权限应使相关会话/权限立即失效。需定义白名单重新加载入口或短周期检测，变更后统一撤销受影响会话。

本机请求也校验 Host/Origin 并限制跨域访问，避免恶意网页借浏览器调用本地写接口。默认不开放任意来源 CORS。

## 5. 权限矩阵

| 操作 | 阅读者 | 编辑者 | 项目管理员 |
| --- | --- | --- | --- |
| 看被授权项目、正文、附件、历史 | 是 | 是 | 是 |
| 搜索被授权内容、导出已授权项目资料 | 是 | 是 | 是 |
| 新建、编辑、上传、设置业务关系 | 否 | 是 | 是 |
| 恢复历史、归档资料 | 否 | 是 | 是 |
| 调整项目成员与角色、归档项目 | 否 | 否 | 是 |
| 管理本地白名单、服务器备份配置 | 否 | 否 | 由主机运维负责人处理，不自动等同项目管理员 |

若需要限制阅读者下载/导出，单独增加权限位；不能承诺允许阅读时可绝对防止复制。P1 不提供不可恢复删除界面；后续垃圾回收与清理需要另行定义授权和保留规则。

## 6. 防越权必查清单

正文、章节、图谱、搜索结果、附件缩略图/原件、历史版本、导出包、导入任务状态全都鉴权。以资源 ID 查所属项目再验证权限，不能只依赖 URL 中的 projectId。搜索先限定授权范围，不能先生成全局摘要再在前端隐藏。

不生成永久公共附件链接；下载走鉴权处理器，缓存策略避免共享代理缓存私有内容。日志记录用户、动作、对象、结果、时间和请求 ID，不记录密码、会话值或完整敏感正文。

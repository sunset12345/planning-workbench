# Google 文档与图示规范（仅明确选用时）

适用于新建、迁移、完整整理及统一格式。当前默认使用 HTML；只有用户明确选择 Google 文档时使用本参考。局部修订匹配周边格式，不擅自重排整份文档。

## 主文档与附件

| 内容 | 正式载体 | 在 Google 文档中的呈现 |
|---|---|---|
| 需求、规则、逐页逻辑 | Google 文档 | 原生段落、标题、列表和表格，可直接修改 |
| 功能思维导图 | 可编辑 `.xmind` | 总览及必要的分支预览，下方放“打开 XMind 源文件”链接 |
| 配置表结构与关系图 | 可编辑 `.xmind`，可与功能导图分工作表存放 | 结构预览、图注、源文件链接；字段字典仍用可编辑表格 |
| UI 示意图 | 保留已有图稿及可编辑源文件（如有） | 各页内嵌清晰图片，附图号、页面 ID 和源文件链接 |
| 配置数据、可玩原型 | 沿用实际文件格式 | 在相关章节放真实附件链接和适用版本 |
| 美术、UI、特效制作需求 | 三份独立 `.xlsx` | 首页及第 10 章放文件超链接，相关章节按需引用 |
| HTML 演示稿（可选） | 自包含 `.html` 或已授权托管页面 | 注明版本和演示范围；Drive 文件注明下载后浏览器打开 |

XMind 中的节点文字、层级和关系线保留独立编辑能力。Google 文档中的预览是静态图片，源文件链接用于获取或打开 XMind 文件；不能承诺点击后直接在 Google 文档内编辑或自动刷新预览。复杂规则流程继续在逻辑章节保留流程图与状态表，不为改用 XMind 丢失条件或分支。

已存在正式 Google 文档时原位更新，保持文档 ID 和入口稳定。文档名称默认“功能名称｜功能策划案”，需要区分项目时加项目名前缀；版本放文档信息区及修订记录，避免每次迭代另建同名正式文档。附件归入用户指定的项目/功能文件夹；未指定时沿用 Google Drive 技能的默认位置。

## 统一章节与排版

按 [功能策划案模板](../assets/功能策划案模板.md) 组织：标题、文档信息、目录，以及 1—9 章。文档信息记录版本、负责人、更新时间、资料来源及附件入口；未知信息如实标注。目录链接到实际标题。无新增或后续补充的章节保留标题和简短范围说明，删除空表、占位符及填写提示。

| 对象 | 默认格式 |
|---|---|
| 文档标题 | Google Docs `TITLE`，22 pt |
| 一级章节 | `HEADING_1`，18 pt，编号 1—9 |
| 二级小节 | `HEADING_2`，16 pt，编号如 3.1、5.2 |
| 三级条目 | `HEADING_3`，13 pt，必要时使用，避免继续堆叠标题层级 |
| 正文 | `NORMAL_TEXT`，11 pt，左对齐，1.15 倍行距、段后 6 pt；字体沿用 Google 文档默认样式并全文一致 |
| 表格 | 原生可编辑表格，10—11 pt，首行是字段标题；统一浅色表头，不用空格模拟列，不用截图代替字段表 |
| 图注 | 10 pt，“图号 · 图名 · 页面/配置 ID · 版本”；源文件链接紧随其后 |

先应用命名样式，再设字号；不只靠手动加粗模拟标题。固定使用同一套标题、图注及编号。默认 A4 纵向、标准页边距；宽表优先按表或子结构拆分，仍需横向时只调整相关部分并检查版面，不缩成不可读的小字。用户选择无分页文档时保留同样的内容与标题规则。

图示按原始比例嵌入。大导图使用“总览＋分支图”，每张都能读清节点；大 UI 图按需补局部图，不能裁掉关键状态或文字。图、正文、字段表顺序对应，不能只在附件里放图而正文没有预览。

## 配置结构图

按真实配置表达“配置表 → 字段/子结构”，表间引用用有方向的关系线，标注“来源表.字段 → 目标表.字段”；一对多、可空和重复限制仅在有依据时标注。没有跨表引用时仍可表达本表层级，注明无跨表引用，不虚构关系。字段字典是类型、默认值、单位、范围与例值的详细依据，结构图不能替代它。

正文中的配置名称、图中节点与实际表名保持一致。配置字段变更时同步结构图、字段字典及涉及的 UI 页；不得把玩家库存、本局进度等动态信息混成静态配置。

## 超链接与版本同步

- 文档内部用真实标题/书签链接连接目录、规则和逐页说明；外部附件用已验证的 Drive 链接，不放本机路径或 HTML 相对路径。
- 每张预览注明对应源文件版本。编辑 XMind 后重新导出预览，替换文档中的图片并记录本次修订；正文改动涉及节点时同步更新 XMind。若本次未完成同步，在对应图旁标明实际版本与待同步状态。
- 更新 Drive 中的 XMind 等普通附件时，工具支持则替换同一文件 ID 的内容；需要新建文件时同步替换正文所有受影响的链接，不留下旧版入口。
- 检查源文件存在、链接目标正确、已有访问范围匹配交付对象；缺权限时说明具体问题，不自动开放公开访问。
- 保留可编辑源文件，不能仅交预览图、改后缀的文本或假定可用的下载链接。仅生成可导入大纲时明确 `.xmind` 未完成。

## 从已有案子迁移

制作需求与可选演示附件遵循 [制作需求附件与 HTML 演示](制作需求附件与HTML演示.md)。正文第 1—9 章保留，第 10 章汇总附件；制作明细不与正文完整复制。

保留原文件作为来源，先盘点章节、规则、图片、表格、导图节点和链接。正文迁为原生文本，字段表迁为原生表格，图示同时保留预览与可编辑源文件。按统一章节安置原内容，保留规则/页面/配置 ID；格式转换不改变玩法，不遗漏原有附录或已经写明的规则。

网页折叠内容在文档中展开或分节整理；原型、筛选、缩放等交互保留在原附件中，通过链接访问，不宣称文档已具有网页交互。迁移范围外的历史资料只作引用，不自动全部上传。

完成后读回 Google 文档，核对章节、正文、表格、嵌入图片和链接；检查导图/配置图节点与源资料覆盖一致。涉及排版时导出 PDF 或在目标应用检查实际显示，特别是宽表、长导图和图注。区分结构检查、视觉检查和 XMind 应用打开验证；上传成功或空白文档创建成功均不等于迁移完成。

# HTML 文档与可编辑图示规范

正式策划案在导入工作台前以 HTML 为单一维护入口；导入并开始在线编辑后以工作台正文为准，HTML 为导出快照。提供侧栏目录、全文检索、折叠内容、大图查看、逐页 UI 和配置表阅读。Google 文档、XMind 仅在用户指定或需要兼容历史交付时使用。

新建或完整整理时同时遵循 [工作台适配与导入规范](工作台适配与导入规范.md)，保留正文稳定标识，生成同版本 `planning.json`。

## 阅读结构

沿用正文模板的第 1—9 章，第 10 章集中放独立制作需求 Excel 和可选演示稿。页首提供版本、更新时间、资料来源和附件入口，不设置完成、审批、验收状态或完整度。首页不设置 `List`、`int` 等数据类型摘要卡片；数据类型、单值/列表和数量约束在配置章节说明。桌面侧栏导航；窄屏可展开目录。规则与公式标题直接写名称，不显示字母编号前缀；正文、导图及附件引用用名称作为链接文字。稳定锚点留在源码中，页面/规则/配置互相跳转。表格在自身容器内横向滚动，不撑宽整个页面。配置字典可折叠，但搜索能找到并展开被折叠的内容。提供打印样式，图和表不裁切。

主文档、演示稿和资源包用清晰文件名；包内链接使用相对路径并核对。正文读取不依赖网络字体、CDN 或临时服务。需要联网功能时明确说明，不能把本地 localhost 当交付链接。云端文件附件只表示访问/下载，未托管的 HTML 不宣称可以在线执行。

## 图示的可维护性

### 思维导图的默认显示形式

功能思维导图统一采用紧凑横向树形显示：白底，从左向右展开；根节点为蓝底白字，一级分支为浅灰底，后续细项为无外框文字；用细蓝色折线连接，同级分支共用连接干线，不加流程箭头。根节点与第一个功能分支对齐。中文按节点宽度自动换行，节点间保留阅读间距。按当前功能的层级与内容组织节点。

参考配色：根节点 `#4c72ff`、分支底色 `#f0f1f3`、文字 `#353940`、连线 `#557aff`；根节点 17px，功能及子功能 14px，末级细项 13px。默认适应宽度，提供全部/单分支、显示层级、放大、缩放、适应窗口/宽度、100% 和下载 SVG；拖动画布平移，滚轮及双指缩放。筛选仅改变阅读视图，完整源数据和保存结果仍保留全部节点。流程图与配置关系图按自身含义保留方向和关系标签。

可复用 [compact-mindmap.js](../assets/compact-mindmap.js) 与 [compact-mindmap.css](../assets/compact-mindmap.css)，生成时内嵌到 HTML，离线打开不依赖 Skill 安装路径。数据结构沿用 `title`、`nodes[{id,text,x,y,w,h,href}]`、`edges[{id,fromId,toId,label}]`。为思维导图标记 `presentation: "compact-tree"`；首次生成调用 `PlanningMindmap.layout(graph)` 排布，读取已保存数据时保留坐标，用户主动选择“自动排布”时才重新排列。新增节点可自动排布并记入撤销历史。

阅读视图在带 `data-graph` 的容器内，向 `.graph-stage` 调用 `PlanningMindmap.mount(graph, stage, {onEdit, onJump})`，两个回调接入当前文档的编辑器和锚点跳转。编辑器复用 `PlanningMindmap.svg(graph, {interactive:false})` 的外观并接入下述编辑操作；阅读和编辑使用同一节点与连线数据。上述资源是布局与阅读组件，需接好编辑、保存逻辑后交付，不将未接入的按钮当作已具备功能。导出清理筛选工具栏及临时平移/缩放状态，以完整源数据重新呈现；导出的 SVG 可按当前所选分支和层级生成。

### 编辑与保存

思维导图、流程图和配置结构/关系图必须保留文本化源数据，如内嵌 JSON、SVG 或 Mermaid 源码。节点有稳定 ID；连线分别保存起点、终点和标签。不能仅嵌截图，也不强制用户跳转 XMind。复杂图拆成可读分图；关系清单可补充图面，但不能用清单冒充连线。

图示支持在源码中直接修改并重新呈现。新建完整交付默认提供直接编辑画布：双击节点修改文字、选中节点后 Tab 新增子节点 / Enter 新增同级节点、拖动位置、撤销/重做、应用/取消，并导出更新后的 HTML。连线自动关联新增节点，拖动时实时跟随；保留连线端点与标签的编辑入口。中文输入法组合输入不能被 Enter 提交打断，快捷键仅在画布内生效。编辑失败保留旧数据并提示具体原因；节点/连线 ID 唯一，拒绝悬空端点。拖动节点后连线跟随。保存动作写入下载文件，不把浏览器暂存或页面变化宣称为原文件已经覆盖。若只提供源码编辑，须明确实际方式。

节点支持可编辑超链接，优先从正文、UI、配置字段表和制作附件中选择，也可填写外部网页地址。默认给对应节点接好实际跳转目标。链接字段随节点数据保存在 HTML 中；阅读视图用独立的跳转按钮，区分选择/双击编辑与打开链接。正文链接使用稳定锚点，跳转时展开被搜索或折叠隐藏的内容；附件使用包内相对路径，外部网页按普通超链接打开。阻止脚本协议等无效链接；未知正文锚点给出提示，不生成看似可用的空链接。

此类交互可接近在线文档导图的直接操作方式；不要宣称已实现多人实时协作、云端自动保存或原文件自动覆盖，除非这些能力确实已实现并验证。

导图数据应能在 HTML 中直接定位，例如带说明的 `application/json` 数据块。代码负责呈现，正文与源数据不要隐藏在难以维护的压缩字符串里。图中的文案以文字节点处理，不将用户输入当任意 HTML 执行。源文件变更同时更新相关正文/配置引用；图上修改不会自动改游戏规则或导表，须明确这一边界。

UI 用内联 SVG 或带可编辑源稿的图示表达，配套逐页交互。允许源码编辑 SVG；提供编辑器时解析检查后应用。区分静态线框与可操作原型。不为“能点”而伪造尚未定义的交互。

## 既有 Google 文档转 HTML

使用现行正文与表格作为内容来源，核对章节、行列、图片、规则和链接。保留既有文件，明确其历史快照身份；尚未导入工作台时 HTML 为后续维护入口；导入后按工作台规范切换，不让两份文档同时声称是最新正式版。无需把本地 HTML 的全文继续同步到 Google。用户明确要求云端副本时再同步，并记录版本。

## 验证

实际用浏览器打开：检索、锚点、折叠、图示放大、双击编辑、快捷新增、连线编辑、拖动时连线跟随、撤销/重做、取消、保存并重开、节点正文/附件/网页超链接、Excel 相对链接及可选演示导航。检查窄屏与桌面溢出、图中文字、表格可读性和控制台错误。导出 HTML 后再次打开验证编辑确实保存；不能只看内存状态。实现范围和验证限制如实交付。

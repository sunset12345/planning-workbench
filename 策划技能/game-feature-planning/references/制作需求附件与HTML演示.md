# 制作需求附件与 HTML 演示

新建完整策划案，或用户要求补齐制作需求时读取。导入工作台前 HTML 文档是正式策划入口；美术、UI、特效需求分别交付独立 `.xlsx` 文件，不把三个工作表放进同一个文件代替独立交付。用户写作“elxs”时按标准 `.xlsx` 理解。

## 三类需求的边界

| 文件 | 内容 | 应具体说明 |
| --- | --- | --- |
| 功能名_美术需求.xlsx | 装备、道具、技能、套装等图标，以及本期确实需要的模型、立绘、贴图 | 独立资源 ID、资源键、关联配置/页面、数量口径、视觉特征、状态变体、尺寸/视角/背景、可编辑源稿及导出格式 |
| 功能名_UI需求.xlsx | 页面、弹窗、通用控件及适配任务 | 页面/控件 ID、入口、信息层级、状态、操作反馈、适配和文字伸缩、所需拆件、关联美术/特效、交付源稿 |
| 功能名_特效需求.xlsx | 战斗技能表现与必要的界面反馈 | 特效 ID、技能/页面/规则引用、触发、附着对象、开始/循环/结束、持续时间、打断/隐藏、叠加/优先级、可读性与性能约束、源文件及预览 |

共同字段包含：稳定需求 ID、名称、制作内容、来源/正文链接、数量和单位（适用时）、新增或复用、交付物要求。需求表说明制作规格，不设置制作完成状态、审批、验收、负责人排期或进度跟踪字段。可用 [字段模板](../assets/制作需求表字段模板.json) 起步，按真实任务增删。

需求清单用于说明制作内容；已有规格注明来源，建议规格就地说明，缺少资料时不编造结论。未提供技术平台时不要虚构面数、粒子预算、引擎格式或性能通过结论。2D 图标需求不自动扩成角色模型制作。数量按独立交付件统计，通用组件引用不重复计数。需求 ID 与运行时配置字段分别标注；新增资源键不能冒充已有配置字段。

美术表拥有内容图标与场景资源，UI 表拥有页面排版和控件，特效表拥有动态表现。跨表用 ID 引用；例如技能图标由美术表定义，UI 行引用其 ID，不重复下单。音效、动画等确需独立分工时按同样规范增设独立 `.xlsx`，不机械生成空文件。

## Excel 与正文

使用可用表格技能生成真正的工作簿。标题标注功能和版本；提供筛选、冻结表头/标识列、换行和合适列宽，检查实际导出文件可读、ID 唯一、引用有效。图稿或正文引用用可点击的包内相对链接或已验证云端链接，不能只填本机绝对路径。不要以 CSV 改名充当 Excel。

HTML 主文档首页附件入口列出三份文件；在 UI/资源相关章节放简短制作范围和文件链接。正文保留功能规则、逐页交互及必要预览，附件维护逐项制作明细，避免两处完整复制。新增正文第 10 章“制作需求与演示附件”用于汇总三表和可选演示稿；前九章编号保持稳定。修订记录注明受影响附件及版本。本地附件沿用文件名和相对路径；使用 Drive 时优先替换同一文件 ID，保持旧链接有效。

## 可选 HTML 演示稿

在用户要求或演示确实有帮助时额外交付 `.html`，通过 HTML 主文档超链接访问。可做翻页讲解、页面导航、状态切换、属性算例；不默认开发完整游戏或可运行战斗系统。按当前任务需要选择演示范围。

优先自包含 HTML，内嵌图稿、样式和脚本，下载后能用浏览器打开。附版本、正文和制作需求入口，明确哪些是静态图、哪些可操作、哪些只是示例值。避免依赖本机绝对路径、临时服务地址、失效图片链接或联网字体。测试上一页/下一页、目录、键盘导航和实际互动。

Drive 上的 HTML 附件链接是文件访问/下载入口，不等于在线执行页面；链接文字写“HTML 演示稿（下载后用浏览器打开）”。已有授权的托管地址时可提供在线演示，并实际打开验证。上传文件不自动授权公开分享或另建公开网站。

## 同步与交付

同一变更同步正文、需求表引用及演示内容；演示稿不取代 HTML 主文档。图示/玩法未变时可沿用旧版本并标明，避免为更新附件虚改所有图注。检查正文链接指向实际文件、工作簿内容与技能/UI 对应、演示附件可离线运行。最终明确更新的主文档、独立附件及实际验证范围。

# 交付细则与检查

完整交付时通读；增量任务只读受影响部分。正式文档及图示遵循 [HTML 文档与可编辑图示规范](HTML文档与可编辑图示规范.md)。字段可拆成多张表，不要求一张超宽表塞入全部信息。

## 功能逻辑

功能概要回答玩家目标、适用对象、开放入口、前置依赖、本期范围和成功/失败出口。

关键流程使用状态转换或条件表表达：

| 当前状态 | 操作/事件 | 前置条件 | 判定优先级 | 数据变化 | 下一状态/UI | 异常与恢复 |
|---|---|---|---|---|---|---|

涉及资源、随机或结算时明确：

- 展示值、判定值和结算值是否相同；单位、取整、上限及等号边界。
- 扣除发生在购买、选择、开始还是成功完成；取消、失败和重试是否返还。
- 随机结果何时生成、保存，哪些操作可以重新抽取。
- 暂离、退出当前挑战、结束整局、断线恢复的区别；保留哪些进度和已消耗资源。
- 多事件同时发生的优先级，例如耗尽资源与胜利同一时刻出现。
- 奖励何时确认、发放、展示；重试、连续点击或恢复时如何避免重复。描述同一奖励只能获得一次等业务结果，不规定通过何种技术机制实现。

在功能规则中说明正常操作及适用边界的结果，包括资源不足、取消、重复操作和中断恢复。无需另外编写验收场景或用例表。

## 配置字段与类型确认

分清 **策划配置、玩家已有信息、本局进度和统计信息**。不要把玩家库存、抽取结果或领取状态当成策划常量表。

字段字典优先说明：表/结构、字段名、业务含义、数据类型、单值/对象/list/map、固定或可变数量、必填/可空、默认值、范围/枚举、单位/精度、关联和确认状态。具体奖励/属性/技能与数值置于配置附件或折叠示例，详细要求见 [程序阅读重点](程序阅读重点.md)。

| 类型问题 | 必须说明的内容 |
|---|---|
| 整数与金额 | 说明是否允许小数、负数、上下限和单位；例如整数份数、金币数量。无需把机器位宽作为策划交付门槛。 |
| ID | 沿用实际类型，可能含前导零、冒号或长整数；不要仅因像数字而改类型。 |
| 浮点、比例与权重 | 概率使用 0—1、百分数还是万分比；精度与取整；权重是否归一化、是否允许 0。 |
| 布尔值 | true/false 或 0/1；缺失值与 false 不应含混。 |
| 枚举 | 值、含义、未知值行为；不能只有 1/2/3 没有解释。 |
| 时间 | 时间戳秒/毫秒或日期字符串，时区、起止边界、空值和永久有效的表达。 |
| 列表/字典/结构 | 元素及子字段类型、固定/可变长度及上下限、顺序、是否允许重复、缺失/null/空列表含义；列表长度和元素内部数量分别说明。 |
| 引用 | 目标表和字段、引用缺失的处理、删除或修改 ID 的影响。 |

沿用已有配置表填写方式。CSV 单元格的外观不能代替类型说明；组合字段给出可理解的子字段定义及填写示例。不要自行重设计导表格式或通信协议。

用“资料已有声明 / 建议类型 / 待确认 / 已确认”区分依据；已有声明仍可能缺单位、范围或空值含义。确认重点是功能需求是否确定，不要求先完成研发技术评审。没有依据时不伪造确认。

检查本次涉及的表：主键唯一、必填、引用存在、范围、枚举、组合字段可解析。只有实际验证过的示例才能称为可导入数据。

## UI 超链接及逐页逻辑

索引覆盖主页面、弹窗、气泡、页签和改变规则的状态。变体可共用图，但在图中或正文明确差异并提供直达链接，不以共用为由省略逻辑。

每页保留：页面 ID、目的、入口/退出、内嵌示意图及源文件链接、控件表、规则、配置引用、玩家信息来源及操作结果。

控件表采用“控件 ID—显示/隐藏/禁用条件—操作—校验—数据变化—反馈/跳转—失败/取消”。按性质合并列；纯装饰内容不列全套逻辑。

列表明确排序、可见行列、滚动/分页、缺图、长名称和数量格式；结果区域明确单项或列表。适用时说明加载、空、锁定、异常、断线、重复点击、返回键、关闭和弹窗层级及状态优先级。图中标注可对应正文；不能只有全页面拼图而无法定位交互。

HTML 内用稳定锚点链接，附件用包内相对链接或已验证云端链接，并检查移动整个文件夹后仍可打开。弹窗总览需指向具体状态说明。

交互表和详细规则对同一行为使用一致的确定表述；例如“当前页面仍显示新标”与“可以保留新标”不是同一约束，需列为待统一项，不能自行择一标为已确认。

## 可编辑导图与可选 XMind

HTML 中保留可编辑的节点/连线源数据和编辑入口，具体遵循 HTML 规范。功能导图以功能结构为主干；配置结构图以表、字段、子结构和引用关系为主干，可在同一 XMind 文件的不同工作表中维护。操作顺序、条件和循环用正文流程图或状态表补充。与正文范围一致，不因简化遗漏功能。

默认在 HTML 中直接编辑节点、层级与连线，支持双击改字、快捷新增及撤销；节点超链接关联正文和附件，随下载的 HTML 一起保存。图注版本与源数据一致。用户另选 XMind 时再附源文件链接与预览，并说明预览更新方式。

仅在用户需要 XMind 时，优先使用可用 XMind 工具、已验证库或已有导出流程。检查实际 `.xmind` 包的内容和树结构，尽可能在目标应用打开检查可编辑性和超链接。仅通过容器/数据结构检查时说明尚未完成应用验证；不能将未验证报告为验证通过。

## 多语言与音效

多语言表：变更类型、Key、源语言文本、占位符及类型、页面/状态、目标语言、长度/换行约束（如有）、翻译状态。语言范围未给出则待确认，不任意扩展。复用文案；复数、数字/日期格式和避免拼接句子按实际需要说明。`UiText` 或中文文案表不代表多语言已完成。

音效表：资源 ID、名称、用途、页面/动作、播放条件、停止/中断条件、循环/并发/冷却（如有）、复用或新增、资源路径及制作/接入状态。按钮动效不能证明已有声音，需求清单不能证明素材已交付。

分别检查配置中的资源路径、实际随包提供的独立文件、HTML/SVG 内嵌资源和外部依赖包。独立文件未随包提供不自动说明内嵌原型无法显示；能在原型看到图像也不代表可编辑源文件、拆件或音频已交付。

## 红点与新标（逐页补充）

每项记录：所属页面/控件、业务条件、数据来源、刷新事件、消除条件、是否向上汇总、是否跨会话保存、数量/优先级（如有）。无汇总红点也可以是一条明确需求。

区分可领奖红点、新内容提示和 NEW 标记；消除时机可能是打开、点击、阅读或领取，不能统一假设进页面即清除。返回、切账号或恢复连接后是否重现由实际需求确定。

## 业务打点需求

统一按业务事件列出：事件名称、想了解的问题、具体触发时机、关联功能/页面、需要记录的信息及其类型、成功/失败/取消的统计含义。不区分客户端或服务器，不要求设计上报接口、关联链路、事件传输或技术去重键。

例如“开始探索”记录实际开始成功的一局，用来统计参与次数；“点击开始探索”记录操作意图，不能算成已成功开始。“撤离成功”只在本局成功结算时记录，重新查看结果页不能重复增加成功局数。说明这个业务规则即可，不规定实现办法。

字段应服务于统计问题，例如地图、难度、挑战类型、结果、失败原因、带出价值。不附加与本功能无关的信息。未确认统计需求时标为建议或后续补充，不为填满章节虚构指标。

## 变更同步与内部自查

制作需求附件按 [制作需求附件与 HTML 演示](制作需求附件与HTML演示.md) 检查：三类独立 Excel、稳定 ID、真实数量、制作与交付状态、正文超链接、可选 HTML 的导航和离线可用性。需求规格与已交付素材须明确区分。

从变更规则检查关联：正文 ↔ 导图 ↔ 页面/状态 ↔ 配置 ↔ 文案/音效 ↔ 红点 ↔ 打点。原型仅在本次任务要求维护时同步；否则记录差异和待同步项，不宣称一致。

自查用于保证内容一致和链接有效，不输出交付检查附录。某条规则未明确时就在该条旁注明；无新增内容或后续补充的模块在对应章节简短说明。需要用户处理的关键问题在回复中说明，不自动建立独立的待确认清单。
